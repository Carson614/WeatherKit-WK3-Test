# WK3 next-hour root-slot reconstruction research

This folder is an isolated experiment based on the accepted MinFix US AQI line and its minute-rain diagnostic copy. Its source and unit-test snapshot is kept on a separate GitHub research branch for review. It is not an installable Surge module. It does not change V1, V2, the accepted AQI test, the earlier diagnostic test, or any iPhone Surge configuration.

## Confirmed device evidence

The Zhangjiajie request included `forecastNextHour`, used `country=CN`, returned HTTP 200, and passed the request/provider/region/replace gates. Its diagnostic said `slot=missing;src=not_called;result=root_slot_missing`. This locates the early return at the WK3 root-table slot check, before ColorfulClouds `/minutely` is called. That old status combined two wire layouts, so it cannot tell whether the root vtable ended before slot 5 or serialized slot 5 with a zero field offset. The captured response body was not available for replay.

The pinned upstream source `patrickyanxxxxx/WeatherKit-WK3` v3.3.6 labels WK3 b66 root slot 5 as `forecastNextHour`; it also documents the six child fields and states that unknown fields require arena preservation rather than decode/re-encode.

## Research implementation

- Reports `root_vtable_short` when slot 5 is beyond the serialized vtable and `root_slot_offset_zero` when the vtable contains slot 5 but its field offset is zero.
- For either absent-slot form, validates the root table and every serialized root child pointer before fetching provider data.
- Builds a new outer WK3 root. It embeds the complete original response as an immutable byte arena, re-links each validated existing root table, and links the encoded next-hour child at slot 5. It never writes to the absent field location or mutates the original byte array.
- Leaves the original bytes unchanged on invalid root/child pointers, provider failure, unverified next-hour structure, conversion failure, or encoding/merge failure.
- The response replay checks the final AQI re-encode after minute injection and compares an opaque slot 17 table before/after.

The re-rooting path assumes each serialized WK3 Weather root field is an offset to a table, matching the current WK3 root processor. It fails closed if that assumption cannot be validated for any present slot. Synthetic tests cannot prove the exact layout of the unavailable Zhangjiajie response.

## Validation and build boundary

The complete local replay ran `npm run build && npm test` and passed 22 tests. The response script is generated by deterministic fixed-anchor augmentation of the verified MinFix bundle; it is not a full Rollup build. The prior full source build was blocked by the private `@nsringo/weatherkit` package returning HTTP 401. No raw iPhone body was exported and no real-device acceptance is claimed.

The GitHub research branch contains the root-slot codec and source-level regression tests, not the generated request/response bundles or a module. Run `npm test` there for the standalone root-slot tests; the additional bundle replay tests are recorded from the local workspace run. This keeps the review branch free of bundled runtime defaults and makes clear it cannot be installed in Surge. The complete 22-test run remains reproducible in the local workspace copy.

The v3.3.6 codec source and Apache-2.0 notice are retained. There is no `.sgmodule` installer in this directory or on the research branch.
